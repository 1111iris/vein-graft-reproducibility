# Reproducible components of the human saphenous vein ex vivo culture response and their partial directional alignment with occluded grafts

Analysis code and result tables for the manuscript "Reproducible components of the human saphenous vein ex vivo culture response and their partial directional alignment with occluded grafts".

All input data are publicly available from GEO (no new sequencing data were generated):

| Dataset | GEO accession | Files used | Role |
|---|---|---|---|
| Augusta culture (discovery) | GSE310013 | `GSE310013_raw_counts.txt.gz` | Bulk RNA-seq, 6 patients, paired day-0/day-7 |
| Lausanne culture (replication) | GSE326710 | `GSE326710_Raw_counts_all_samples.csv.gz` | Bulk RNA-seq, 4 patients, paired day-0/day-7 |
| Augusta spatial | GSE310351 | GSM9294393–GSM9294398 (matrix/features/barcodes/tissue_positions) | Visium FFPE, 3 patients, paired sections |
| Lausanne spatial | GSE299685 | `GSE299685_Normalized_Counts.xlsx` | GeoMx, 4 patients, media vs intima/adventitia ROIs |
| Occluded grafts (clinical calibration) | GSE241205 | `GSE241205_gene_fpkm.txt.gz` | Bulk RNA-seq (FPKM), 3 patients, occluded vs spare vein |

Raw files are not redistributed in this archive; download them from GEO before running.

## Repository layout

- `R/` — analysis scripts, run in numeric order (see below)
- `results/` — all result tables (CSV) produced by the scripts, including `results/supplementary_tables/` (manuscript Supplementary Tables S2-S11)
- `figures/` — the four final manuscript figures (PNG/SVG)
- `gene_sets/` — the locked analysis plan (original Chinese document, locked 2026-10-29 before the formal analyses; English version in Supplementary Material S1 of the manuscript)
- `sessionInfo.txt` — full R session information (also Supplementary Material S2)
- `renv.lock` — locked dependency versions (R 4.4.2 and 100 packages). Restore with `renv::restore()` in a fresh R session before running the chain; the direct dependencies are limma, edgeR, DESeq2, fgsea, ggplot2, Matrix, readxl, patchwork, and svglite (needed by the figure scripts' `ggsave(..., .svg)` calls; it was missing from earlier lockfiles)

## Clean-machine reproduction check (2026-11-04, round 17)

The full chain was re-run on a separate machine that shared only the base R installation (R 4.4.2) and no project state: `renv::restore()` from this lockfile, `00_download_data.R` into an empty `data/`, then scripts 10-25 and 17-20 in the execution order above. Every result CSV was byte-identical to the archived versions, and the four figures were identical in vector (SVG) content; PNG files differed at the byte level only through the rasterization backend, not the plotted content.

The empty-directory run exposed and fixed three defects that the original machine had masked because its `data/` directory was already populated:

1. **Visium URL pattern (`00_download_data.R`):** the sample-level URLs repeated the full GSM accession where GEO expects the `GSMxxxxxnnn` directory prefix (e.g. `samples/GSM9294nnn/GSM9294393/suppl/...`), so all 24 Visium files failed to download. Fixed.
2. **Missing GeoMx annotation download (`00_download_data.R`):** scripts 11 and 14 parse `!Sample_title` from 36 per-ROI SOFT pages (`geo_pages/gsm299685/GSM9043727-GSM9043762.txt`) that existed only on the original machine and were never downloaded by the script. The script now fetches them from the GEO `acc.cgi` text endpoint.
3. **SHA-256 helper (`00_download_data.R`):** `openssl::sha256(file(path))` opens the connection in text mode by default, which yields an incorrect digest; fixed to binary mode (`open = "rb"`). Manifests generated by earlier versions should be regenerated by deleting `data/manifest_sha256.txt` and re-running the script.

`renv.lock` now includes svglite (see lockfile note above). System prerequisite when restoring from source: `systemfonts`/`textshaping` (svglite dependencies) require freetype, libpng, and fontconfig headers; on conda-based R installations, point `CPATH`/`LIBRARY_PATH`/`PKG_CONFIG_PATH` at the conda environment's `include/` and `lib/` directories if the compilers cannot find them.

## Round-24 correction (2026-11-07, after the v18 review): bidirectional archive comparison

The v18 entry script compared the fresh run against the archived reference in one direction only: it walked the files the fresh run produced and checked each against the reference, so an archived output that a code regression silently stopped generating would never be visited. The comparison is now bidirectional: the expected file set comes from the archived reference, the actual set from the fresh run, and the verdict fails on ANY of (a) archived outputs not regenerated, (b) unexpected extra files, (c) content differences, in addition to the per-script and key-check failures. The four figure SVGs and the 13 supplementary tables are additionally asserted by name, so output completeness never depends on static path extraction from the scripts (an extraction that finds nothing can no longer pass silently). A `--compare-only` mode re-runs the checks, comparison, and verdict against an existing `results/` without repeating the download and chain.

Both paths were verified by execution: a doctored reference containing one file the run cannot produce made the audit FAIL with exit status 1 and name the missing file; the clean run from an empty directory (fresh download of all 64 source inputs, full chain) PASSED with exit status 0 — 16/16 scripts, 23/23 checks, 53/53 comparable outputs byte-identical, 0 missing, 0 unexpected, 0 missing named figures/tables.
